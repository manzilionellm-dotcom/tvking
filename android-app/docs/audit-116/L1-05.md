# L1-05 — Ouverture du Direct avec index et génération

La sélection garde le lot réellement affiché et sa génération. Elle prépare
une seule fois sa file autorisée, puis vérifie après chaque attente le profil,
la portée, les restrictions, l’identité du snapshot et de l’index `_byId`.
L’autorisation de la chaîne sélectionnée reste vérifiée : être dans l’index
ne donne jamais un droit de lecture. Le premier build différé de la route
revalide aussi la sélection avant de construire le lecteur.

Les callbacks d’une carte et d’une ligne capturent leur sélection au rendu.
Ils ne relisent plus une autre chaîne qui aurait entre-temps pris le même
index. Un événement de catalogue déjà en file est remplacé par le snapshot
actuel du dépôt avant de reconstruire l’index.

`RepairFlags.liveOpenIndexLegacy`, clé `zuno.direct.open_index_legacy`, vaut
`false` par défaut. `true` remet le calcul répété historique pour le diagnostic.
Les gardes de génération et de permission restent actives dans les deux
chemins. Aucun comportement de 7 MOTION, réglage du moteur, identité ou donnée
persistante n’est modifié.

## Vérification locale

Les 17 tests du helper et les six tests widget couvrent la chaîne autorisée,
absente et interdite, le profil remplacé, le catalogue remplacé, une sélection
ancienne, les attentes de l’aperçu et l’intervalle entre push et premier build.
Les huit tests existants du Direct et de ses accès adultes passent avec eux :
31 réussites dans une exécution. Un test supplémentaire couvre le drapeau et
son défaut en cas de préférence illisible. Aucun test existant n’a été changé.

Les tests widget `tv_live_open_generation_test.dart` utilisent les API déjà
présentes dans le 116. Deux échecs fonctionnels ont été reproduits sur ses
sources intactes : ancien callback après remplacement du catalogue et profil
changé entre `push` et premier build du lecteur. Les quatre autres scénarios
passent déjà sur le 116. Les six passent sur la correction.

Une première tentative a été refusée par le contrôle automatique pour un
accès GitHub non expliqué. L'exécution retenue utilise un nouvel espace réseau
Linux, dont le lanceur vérifie l'absence de toute interface externe et de
route : seule la boucle locale est active. Le même dispositif, les mêmes
fichiers de tests et le même verrou de dépendances sont utilisés avant/après.
Les journaux sont `evidence/base/l1-03-l1-05-regressions-offline.log` et
`evidence/l1-03-l1-05-regressions-offline-green.log`. Le second comporte neuf
réussites, dont les six scénarios L1-05, la capture existante et les deux
régressions parentales L1-03. Aucun accès GitHub n'est possible dans cet espace.

Le test de coût compte des consultations de collection dans un scénario
de 50 000 chaînes ; il ne mesure pas un temps de réponse sur appareil. La
capture Direct du candidat est produite par le test existant, avec fixture,
langue, thème, résolution et échelle fixes. La comparaison avec le 116, la CI,
l’APK et les mesures physiques restent des preuves distinctes.
