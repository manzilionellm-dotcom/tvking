# L1-01 — Watchdog DLNA et annulation de la requête expirée

## Portée et état

Cette implémentation a été reconstruite après la perte de l'environnement
local. Les résultats de l'ancienne implémentation ne constituent pas ses
preuves. Le patch annoncé `zuno-116-lot1.patch` n'était pas disponible : il
n'a pas été appliqué ni présenté comme relu.

Le défaut observé dans le code du 116 est une sonde périodique de 10 secondes
dont `GetTransportInfo` peut attendre 15 secondes. Le garde de reconnexion
précédait cette attente ; deux sondes pouvaient donc réagir à la même coupure.

Les changements concernent `cast_manager.dart` et `upnp_av_transport.dart`.
Ils sont limités à `AppPlatform.isZuno`. Le chemin historique de 7 MOTION
reste explicite et dispose de tests de conservation de comportement.

## Comportement

- Le propriétaire unique du watchdog est pris avant `GetTransportInfo` et
  conservé pendant toute la reprise. Le `finally` ne libère que son propre
  jeton ; une ancienne session ne peut libérer celui de sa remplaçante.
- Après l'attente et entre les commandes SOAP de reprise, le moteur vérifie
  la session, le transport, la pause ou l'arrêt, la sélection, le profil et
  les autorisations. Une réponse obsolète n'envoie pas la commande suivante.
- Chaque requête SOAP du nouveau chemin possède son propre client HTTP.
  À son échéance, ce client est fermé. Ni les commandes parallèles du même
  transport ni celles d'une autre session ne partagent ce client.
- Le Stop explicite reste disponible pour nettoyer une session révoquée.
  Les gardes de sécurité ne sont pas désactivés par le retour arrière.

## Interrupteur et retour arrière

`RepairFlags.dlnaWatchdogLegacy`, clé `zuno.dlna.watchdog_legacy`, vaut
`false` par défaut. Sur ZUNO, `true` rétablit la concurrence et le timeout
historiques, tout en conservant les contrôles de session et d'autorisation.
Sur 7 MOTION, cette correction ne sélectionne jamais le nouveau chemin.
Il ne faut pas utiliser ce repli comme moyen d'autoriser un contenu interdit.

Aucun réglage vidéo protégé, package, signature, schéma SQLite, plafond
mémoire, donnée client ou dépendance n'est modifié par cette correction.

## Scénarios de validation

Les fichiers portables ne dépendent que d'API présentes au 116. Ils peuvent
donc démontrer un échec fonctionnel sur cette référence, sans échec causé
par l'absence d'un nouveau symbole.

| Fichier | Vérifications |
| --- | --- |
| `dlna_watchdog_regression_test.dart` | Récepteur SOAP STOPPED après 12 s, une SetURI par coupure ; pause ; arrêt ; remplacement de session et ancien finally ; profil ; restrictions ; erreur ; timeout et réponse tardive ; 7 MOTION |
| `upnp_timeout_cancellation_test.dart` | Vraies sockets locales : fermeture à échéance, Pause parallèle et autre transport conservés ; réponse tardive ; absence d'annulation nouvelle pour 7 MOTION |
| `upnp_recovery_guard_test.dart` | Révocation pendant Stop, GetTransportInfo, SetURI et Play ; arrêt de nettoyage ; repli conservant les gardes ; chemin 7 MOTION |

L'horloge simulée conserve les délais de 10 et 12 secondes du scénario
fonctionnel. Le test du propriétaire observe jusqu'à 52 secondes simulées,
après le retour d'une seconde sonde qui révélerait une libération incorrecte.
Les tests de sockets utilisent uniquement la boucle locale, dans un espace
réseau sans route externe. Ils observent réellement la fermeture côté serveur.

Les exécutions locales de la reconstruction du 11 novembre 2026 utilisent
Flutter 3.47.7 stable et Dart 3.13.5, avec le même lock de dépendances dans les
deux espaces. Les sources de production du témoin sont intactes ; seuls les
nouveaux tests portables et leur fixture sont ajoutés. Le worktree témoin utilise le commit exact
`a4b81f7661d05866a39eeb05eec040ddbb1b7eb0`, arbre
`13d5ef7848c92a50c0fdf613f5cceed0def95030`.

Le défaut principal est reproduit : le témoin envoie deux `SetAVTransportURI`
après une seule coupure STOPPED retardée de 12 secondes ; le candidat en
envoie une. Le scénario d'ancienne session donne également deux reprises
sur le témoin et une sur le candidat. Les tests HTTP échouent sur le témoin
parce que la fermeture de la socket n'arrive pas à l'échéance observée.
Les scénarios de conservation du chemin 7 MOTION passent dans les deux
espaces. Le contrôle de révocation des restrictions est testé avec le
complément parental L1-03 intégré.

Le commit L1-01 contient 18 de ces tests ; le scénario transversal de
révocation des restrictions est ajouté avec L1-03. Les 19 scénarios L1-01
intégrés font partie d'une exécution de 37 nouveaux scénarios
Cast/contrôle parental, tous réussis, code de sortie 0. Les journaux sont
conservés hors du dépôt de travail sous
`evidence/recovery/cast/candidate-new-tests-01.log` et
`evidence/recovery/cast/baseline-portable-tests-01.log` ; le manifeste
`baseline-fixture-manifest-01.json` conserve les empreintes identiques des
tests. L'exécution porte sur les sources de travail reconstruites, avant

rétroactivement.

La suite locale complète `test/features/cast` et `test/features/tv/desktop`

existante. Elle contient les 37 nouveaux scénarios et 245 tests existants.
Son journal est `candidate-cast-desktop-suite-01.log` dans le même dossier.

L'analyse ciblée des quatre sources Cast/Desktop et des nouveaux tests ne
trouve aucune erreur ni nouveau diagnostic. Elle conserve 3 avertissements
et 17 informations préexistants ; son code de sortie 2 n'est pas présenté
comme un succès d'analyse sans réserve. La comparaison machine avec le
116 est consignée dans `analysis-comparison.json`.
